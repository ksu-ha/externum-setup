# Архитектура Externum Setup

## Общая схема

1. Графический интерфейс (PyQt5) собирает параметры (IP, SSH, NTP, ISO) и передает их в оригинальный скрипт.
2. Оригинальный `install.sh` вызывается в CLI-режиме (`--mode cli`) с аргументами `--system-type`, `--project-server`, `--user`, `--apt-iso` и т.д.
3. `install.sh` самостоятельно создает `/tmp/inventory.yml` с SSH-данными.
4. `install.sh` вызывает `under-install.sh`, передавая ему нужный Ansible playbook.
5. `under-install.sh` запускает Ansible playbook (`install-single-node.yml` или `install-multi-node.yml`).
6. Ansible разворачивает Docker-контейнеры Externum на целевом сервере.

## Разделение ответственности

1. **GUI (PyQt5):** Сбор параметров, валидация (IP, SSH, NTP, ISO), визуализация прогресса, сбор диагностики, формирование отчета TAR.GZ.
2. **install.sh:** Оригинальный скрипт от РЕГЛАБ. Мы не переписываем его. Он отвечает за создание `inventory.yml` и запуск Ansible.
3. **Безопасность:** Пароль SSH передается в `install.sh` через переменную окружения `EXTERNUM_SSH_PASSWORD`, а не через аргументы командной строки. В логах и отчетах пароли маскируются с помощью `core/security.py` (regex-паттерны `password=`, `token=`, `Bearer`).

## Демонстрационный режим

1. Для безопасной демонстрации без реальной установки Docker-контейнеров используется stub-скрипт `usb-disk/install.sh`.
2. Stub-скрипт принимает те же аргументы, что и оригинальный скрипт.
3. Stub-скрипт возвращает коды `0` (успех) или `5` (ошибка).
4. Это позволяет показать интеграцию без 40-минутной установки.
