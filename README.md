# Externum Setup

Графический установщик (GUI) и мастер подготовки комплекса Externum для Astra Linux.

## Описание

Проект представляет собой графическую обёртку (wizard) для оригинального консольного установщика Externum, предоставленного ООО «РЕГЛАБ» в составе архива `usb-disk`. 

Установщик не изменяет внутренние скрипты `install.sh`, а вызывает их в **CLI-режиме** (`--mode cli`), передавая все необходимые параметры через аргументы командной строки. Это позволяет сохранить оригинальную логику установки, скрыть её за понятным пошаговым интерфейсом и снизить риск ошибок при ручном вводе.

## Возможности

- Графический мастер на PyQt5 (7 экранов: Интро, Проверки, Сеть, ISO, Обзор, Выполнение, Результат).
- Девять предварительных проверок (ОС, архитектура, сеть, APT, ресурсы, ISO, usb-disk, Docker, интерфейсы).
- Круговой индикатор готовности с подсчётом пройденных проверок.
- Валидация сетевой конфигурации (IP, CIDR, шлюз, DNS, SSH-логин, NTP, сервер истории) с подсветкой ошибок прямо под полями.
- Карточка настройки PRP-интерфейса (с возможностью продолжить без PRP).
- Выбор ISO через диалог, проверка сигнатуры ISO 9660, монтирование в режиме read-only, подключение как локального репозитория.
- Запуск оригинального `install.sh` в CLI-режиме с передачей параметров.
- Безопасная передача SSH-пароля через переменные окружения (не попадает в аргументы командной строки и логи).
- Отслеживание прогресса и вывода сценария в реальном времени.
- Обработка ошибок с возможностью повтора операции.
- Маскирование секретов в логах и отчётах.
- Экспорт диагностического отчёта TAR.GZ с выбором папки сохранения.
- Демонстрационный режим (безопасная симуляция для Windows и тестирования).

## Требования

Для разработки и запуска:
- Python 3.9+
- PyQt5
- PyYAML
- pytest (для тестов)

Для реального выполнения:
- Astra Linux (версия 1.8.3 и выше)
- Права суперпользователя (root) для системных операций
- Утилиты `bash`, `mount`, `umount`, `ip`, `tar`, `docker`
- Оригинальный архив `usb-disk` (распакованный)

## Запуск в Astra Linux

### 1. Установка системных зависимостей

```bash
sudo apt update
sudo apt install -y python3-pip python3-venv \
    libxcb-xinerama0 libxcb-cursor0 libxkbcommon-x11-0 \
    libxcb-util1 libgl1-mesa-dev libfontconfig1 libqt5gui5
```

### 2. Создание виртуального окружения и установка Python-библиотек

Так как в Astra Linux уже есть системный PyQt5, мы создаем окружение, которое видит системные пакеты. Это предотвращает конфликт библиотек.

```bash
cd externum-setup-main
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Запуск приложения

```bash
python main.py
```

Для реальной установки приложение необходимо запускать с правами администратора:

```bash
sudo -E .venv/bin/python main.py
```

## Запуск в Windows

В Windows доступен только демонстрационный режим (реальные системные изменения не выполняются).

## Интеграция с оригинальным install.sh

GUI вызывает оригинальный скрипт `install.sh` в CLI-режиме со следующими аргументами:

```bash
sudo bash install.sh --mode cli \
  --system-type centralized \
  --project-server 192.168.1.10 \
  --user admin \
  --ntp-server 10.0.0.20 \
  --apt-server 192.168.1.10 \
  --apt-iso /path/to/astra.iso
```

SSH-пароль передаётся через переменную окружения `EXTERNUM_SSH_PASSWORD`, а не в аргументах командной строки. Это предотвращает его утечку в логи или отчёты.

Скрипт `install.sh` самостоятельно создаёт `/tmp/inventory.yml` и вызывает `under-install.sh` с нужным Ansible playbook (`install-single-node.yml` или `install-multi-node.yml`).

### Демонстрационный режим

Для демонстрации на защите или в среде без прав root можно использовать stub-скрипты (заглушки), которые принимают те же аргументы, но не выполняют реальных изменений. Пример такой заглушки находится в папке `demo/usb-disk/install.sh`.

## Сборка бинарника

Для получения единого исполняемого файла (без необходимости установки Python и библиотек):

```bash
pip install pyinstaller
pyinstaller --noconfirm --clean --onefile --windowed --name ExternumSetup main.py
```

Результат: `dist/ExternumSetup`. Положить его рядом с `README.md` и папкой `usb-disk`.

## Тестирование

```bash
pip install -r requirements-dev.txt
python -m pytest tests -v
```

## Журнал и диагностический отчёт

Логи сохраняются в:
- Linux: `~/.local/state/externum/logs/`

В диагностический отчёт TAR.GZ входят:
- `report.json` (состояние, версия, этап, ошибка, последние 100 строк лога).
- `diagnostics.json` (маршруты, сеть, версии Docker, источники APT).
- `README.txt` (с рекомендациями по устранению неполадок).
- `logs/externum.log`.

Секреты (пароли, токены, ключи) автоматически маскируются. Файл `config.yml` с паролями по умолчанию в отчёт не включается.

## Известные ограничения

1. Оригинальный `install.sh` по умолчанию интерактивен (использует `whiptail`). GUI вызывает его в CLI-режиме (`--mode cli`).
2. Реальная установка Docker-контейнеров требует 32 ГБ RAM и 100 ГБ диска. В демо-режиме эти проверки выводятся как предупреждения и не блокируют установку.
3. Для демонстрации используется stub-скрипт, который возвращает коды `0` (успех) и `5` (ошибка).
4. В Windows реальные системные операции недоступны (только демо-режим).
5. Для монтирования ISO и настройки PRP требуются права root.
